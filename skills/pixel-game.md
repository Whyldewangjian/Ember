# 技能：像素 / 2D 游戏的具体规格

> 这份是"数字和做法"，不含流程。流程在 Agent 预设里。
> 做像素或 2D 游戏前先读这份，按里面的数字执行。

## 一、画幅与像素密度

- 逻辑分辨率（跟 PRD 第 1 章一致，不许改）：
  640x360（默认，放大 3 倍到 1080p）
  480x270（更复古，颗粒更粗）
  960x540（更细，接近 HD-2D 角色精度）
  竖屏对应：360x640 / 270x480 / 540x960
- 整数倍放大，禁止非整数缩放，禁止用 devicePixelRatio 缩放画布
- 瓦片 16x16，坐标必须能被 16 整除
- 角色高度取逻辑高度的 1/6 到 1/4（640x360 时约 60 到 90 像素）
- 细节像素 8 / 4 / 1，逐级递减

## 二、色板结构（按实测基准来）

**下面是拿一张高水准像素场景（小岛）实测出来的数字，按这个做：**

| 指标 | 合格线 | 那张图实测 |
|---|---|---|
| 同屏有效色数（5bit 量化、面积 ≥0.15%） | ≥ 80 | 82 |
| 加权平均饱和度 | ≥ 50% | 54% |
| 高饱和颜色（S≥70%）面积占比 | **≥ 15%** | **29%** |
| 大面积基色饱和度 | ≥ 35% | — |
| 色相数（占比 ≥2%） | 3 到 8 个 | 8 |

**最关键的是"高饱和面积 15%"这一条。** 画面发灰、像 8 位机，几乎都是因为它：
高饱和色只点在小花上（1.5%），而大面积的草地/水全是低饱和。

做法：
- 水用亮青（S 90% 左右）、受光叶片用亮黄绿（S 75%）、沙滩木屋用暖橙（S 60%）
- 底色选"浓"的：草地用 S 45% 以上的青绿，不要灰绿
- 暗部用"更暗 + 更浓"，不要加灰（加灰就是降饱和，越画越灰）
- 每个主色 5 档明暗：8 个色相 × 5 档 = 40 色打底，加材质与光效中间色轻松到 80 以上
- 过渡用 2x2 棋盘抖动（覆盖率 55%），抖动本身也会增加有效色数
- 描边用同色系最暗色，禁止纯黑（剪影层除外）

色板表格式：

    色相 | 用途 | 5 档 hex | 饱和度
    青绿 | 植被 | #1b3a2a #2a5c3f #3f7d52 #5aa066 #86c47b | S 35 到 55%
    暖金 | 强调 | ... | S 80 以上，面积约 5%

## 三、分层与光

分层：
- 至少 3 层：远景（视差 0.2 倍）/ 主体（1 倍）/ 前景遮挡（1.3 到 1.6 倍）
- 远景做空气透视：色相向天空色偏移、对比度降低、细节减少
- 前景用暗剪影（草叶、柱子、窗框）

光：
- 只设一个主光源，方向全程一致，阴影方向必须和它一致
- 暖光配冷影或冷光配暖影
- 高光只在受光侧，宽 1 到 2 像素；背光侧 1 像素边缘光

光感表达三选一（按场景，不要每次都用同一种）：
1. 明暗对比：任何场景都成立，最不会出错
2. 边缘光：适合逆光、剪影
3. 体积光（光束）：只有"有明确方向主光 + 空气里有雾/尘/水汽"时才用

光束的禁令：
- 纯俯视地图不要画（俯视看不到光路，只会变成贴在地上的白条）
- 室内、夜晚、阴天、无尘不要画
- 不许每屏都加；方向必须与主光和阴影一致

光晕（bloom）：把高光区加色叠一层模糊小图，强度不超过 0.3

动态光影：
- 火焰/灯笼：2 到 3 帧抖动，半径轻微呼吸
- 水面：横向 UV 位移或 3 帧循环
- 雾：两层，不同速度，透明度 0.15 到 0.3

## 四、资产怎么做

优先级（从上到下）：
1. 优先用图片资产（assets/ 里的 png），代码只做 drawImage + 逻辑
2. 没有资产时才用代码画，并告诉用户"这是临时占位美术"
3. 绝不用"文字描述"去重画本来可以有图的东西

- concept/ 里的概念图只用来定风格和配色，不进游戏
- 要用的图必须按网格尺寸单独生成到 assets/，不许从概念图里抠
- 场景用图形基元加抖动纹理程序化绘制（砖、瓦、木纹、草）
- 字体：优先 canvas 手绘 8x8 或 6x8 点阵字；中文用系统字体但小号、无抗锯齿
- 禁止：直接贴 jpg、用模糊图片、用大 png 缩到小尺寸

动画：
- 有角色：待机 2 帧、行走 4 帧，靠像素数组替换整帧；位移用 tween，形变用 squash/stretch
- 无角色（塔防/经营/解谜）：炮塔旋转瞄准 + 开火后座 2 到 3 像素 + 炮口闪光 1 帧；
  设施待机呼吸 1 到 2 像素；受击闪白 60 毫秒
- 不做 sprite sheet 切图，帧就是数组
- 逻辑 60fps，动画切换 6 到 10 帧每秒

## 四.5、场景怎么画（有素材包时）

**有 tileset 就不要再用代码画格子。**

1. 先调 `tileset-preview`（sheet / tileSize / cols / rows），生成 `tiles.json` + 带编号的预览页
2. 让用户打开预览页，报几个关键地块的编号（比如 11=草地、21=水、66=土路、19=灌木）
3. 把这些名字写进 `tiles.json` 的 `names` 字段：`{"11":"grass","21":"water"}`
4. 地图用**编号二维数组**表示，不要写像素坐标：

```js
const map = [
  [11, 11, 12],
  [66, 66, 12],
  [21, 21, 12]
];
```

5. 游戏里按编号贴图（精灵表方式，不切图）：

```js
this.load.spritesheet('terrain', 'assets/tiles/sheet.png',
  { frameWidth: TILES.tileSize, frameHeight: TILES.tileSize });
this.add.image(c * TILES.tileSize, r * TILES.tileSize, 'terrain', map[r][c]).setOrigin(0, 0);
```

**没有素材包时才退回代码绘制，并且要告诉用户"这是临时占位画面"。**

**CC-BY 的素材必须在游戏里署名**（比如结尾或设置页放一行"素材来自 XXX"）。

## 四.6、挑图块的三看（踩过坑，必须照做）

只看编号挑图块一定会出错。每选定一个关键图块，做这三件事：

1. 放大看（预览页开 6x）：这一格里到底画的是什么？有没有被裁断？
   实际踩过的坑：#77 那一格里塞了两棵小树，右边那棵被格子边界裁掉了一半。
   直接铺上去，草地上会多出一条竖着的黑缝 —— 看起来像 bug，其实是素材本身这样画的。
   换成 #76（一棵完整的大树，带土坑底座）就没有这个问题。

2. 看透明度：tiles.json 里 alpha < 0.65 的才是可叠放块（树、石头、道具），
   不透明的只能铺地面。拿不透明的当树用，会出现一块黑底方块。

3. 连铺 4 格看接缝：把同一个地块横向铺 4 格、纵向铺 4 格，看有没有一条明显的线。
   有的话说明这块不适合做地面。

关于索引里的 edge 字段：它统计边缘像素有多暗，能提示可能存在的接缝，
但它会把砖墙、木箱这类本来就有深色描边的图块也标出来（实测这套素材 120 块里有 54 块被标）。
所以 edge 只能当提醒，不能当结论 —— 最终还是要靠放大看 + 连铺看。

另外：素材图直接双击打开时，如果页面变成一片绿色斜线格子，那是缺图占位符，
不是素材坏了。把素材内嵌成 base64 可以避免这种本地文件的加载限制。

## 五、技术规格

- Phaser 3，物理用 Arcade；多文件用经典脚本（script src），不要用 ES module
  （ES module 双击打不开，会有 CORS 问题）
- 引用 Phaser 一律写 script src="phaser.min.js"，不要写 CDN 网址；
  程序会在写出含 phaser 的 HTML 后自动把库放进同目录
- 触屏必做：虚拟方向键/摇杆（仅触摸设备显示）、按钮不小于 44 像素、
  禁双指缩放、上滑不滚页、竖屏提示
- 右上角暂停按钮，固定不被遮挡
- 音频可以没有；有就用 WebAudio 合成，不要外部文件
- 不引入任何 CDN 资源

## 七、自检清单（逐条打勾）

画面：
- 截一张静帧，像一张像素插画（不是色块拼贴）
- 3 层以上景深，前景有遮挡
- 有主光源、有暖冷对比；光感表达与场景匹配，且说明了用哪种、为什么
- 大面积基色不发灰：草地/地面/天空的饱和度都到 35% 以上
- 至少一个 80% 以上饱和度的强调色，且在画面里占得出一块面积
- 主要东西有 1 像素深色描边，受光侧有高光
- 纯黑剪影能认出是什么、在做什么
- 除雾和光效外没有半透明渐变
- 按 PRD 的画幅放大到全屏不模糊、不拉伸

交付前报三个数字（自己量，不许瞎写）：
- 实际用到的色相数
- 大面积基色的平均饱和度
- 最高饱和度是多少、大约占画面多大比例、用在哪

玩法：
- 打开就能操作，无需说明
- 操作有视觉反馈（闪白、粒子、抖动）
- 没有穿墙、没有卡在地面
- 失败有提示且能重开

对外：
- 双击 index.html 能玩，不依赖网络
- 手机横屏可玩，按钮不小于 44 像素
- 同目录有 phaser.min.js（如果用了 Phaser）
- 帧率稳定 60
- 代码里没有 TODO、没有占位色块、没有未完成的分支

## 八、禁止事项

- 禁止把 PRD 分多次写同一个文件（会被覆盖）
- 禁止在游戏代码里顺手画角色
- 禁止用纯几何基元交差（一个三角形当山、一个矩形当人）
- 禁止没有雾或尘却画光束；禁止每屏都加光束
- 禁止说"完成"却没跑过 check-page
