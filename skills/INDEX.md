# 技能索引

> 放在 `<工作文件夹>\skills\INDEX.md`。
> Ember 的 Agent 每轮会自动读到这份索引（最多 2500 字），
> 然后在做相关任务前用 read 打开对应的技能文件，按里面的流程和规格执行。
>
> 原则：索引常驻（便宜），正文按需读（可以写很长）。

## 什么时候先读技能

用户提到下面这些词，就先读对应文件，再动手：

- **像素游戏** / 做一个游戏 / 游戏开发 / PRD / 关卡 / 玩法设计
  → `skills/pixel-game.md`
- **角色** / 精灵图 / 精灵表 / sprite / spritesheet / 帧动画 / 行走动画 / 待机动画 /
  敌人 / NPC / 立绘 / 像素小人 / 塔的外观
  → `skills/pixel-sprite.md`

**拿不准的时候：先 read `pixel-game.md`，它的第一步会告诉你接下来该读哪个。**


## 模板

- `templates/sprite-preview.html` —— 通用「精灵动画验收台」
  做法：复制到 `assets/<类型>/<名字>/preview.html`，同目录放 `sprite.js` 即可。
  只要 sprite.js 暴露 `window.Sprite`（或任意带 makeCanvas 的全局对象），
  页面自动生成方向按钮、播放/暂停、逐帧、速度、帧条、色板 —— 不用改模板。

## 新增技能时照这个格式

```markdown
# 技能：名字

## 适用场景
一句话说清什么时候用。

## 铁律
写"顺序"和"禁止"，模型最容易违反的放最前面。

## 规格
尺寸、色值、帧数、命名 —— 必须是数字和具体值。

## 步骤
1. ...
2. ...

## 自检清单
- [ ] ...

## 禁止事项
- ...
```

**加技能时记得两件事：① 在上面的"触发词"里补上用户会说的词 ② 在"什么时候先读技能"里加一条。**
